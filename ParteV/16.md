## 16. Caso Block Storage

### PostgreSQL sobre un volumen

PostgreSQL requiere un sistema de almacenamiento que permita:

* Escrituras parciales.
* Acceso aleatorio.
* Persistencia.
* Sincronización.
* Operaciones frecuentes.
* Baja latencia.

Por ello, normalmente utiliza Block Storage y un sistema de archivos.

Arquitectura conceptual:

```text
PostgreSQL
    |
    v
File System
    |
    v
Ceph RBD
    |
    v
Ceph Cluster
```

### Disco persistente

Un volumen RBD puede presentarse como un dispositivo de bloques.

El sistema operativo puede formatearlo y montarlo.

### Random I/O

Las bases de datos realizan operaciones de lectura y escritura sobre diferentes regiones del almacenamiento.

Este patrón es distinto al de Object Storage, donde normalmente se recupera o reemplaza un objeto completo.

### Snapshots

RBD permite crear snapshots de volúmenes.

Los snapshots pueden utilizarse para:

* Recuperación.
* Clonado.
* Pruebas.
* Backups.
* Restauración rápida.

No sustituyen por sí mismos una estrategia completa de backup de base de datos.

### Concepto de RBD

RBD distribuye los bloques entre los componentes de almacenamiento de Ceph.

La aplicación consume un volumen, mientras que Ceph administra:

* Distribución.
* Replicación.
* Recuperación.
* Redundancia.
* Rebalanceo.
