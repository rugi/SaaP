## 14. Riesgos de una migración

### Consistencia

El contenido del origen puede cambiar mientras se ejecuta la migración.

Debe definirse:

* Si se permiten escrituras.
* Si habrá una ventana de congelamiento.
* Si se ejecutará una sincronización final.
* Cómo se detectarán cambios.

### Objetos que cambian durante la copia

Un objeto podría modificarse después de ser listado y antes de ser copiado.

Posibles estrategias:

* Validar fecha de modificación.
* Validar versión.
* Calcular checksum.
* Repetir la copia.
* Ejecutar una fase de reconciliación.

### Archivos grandes

Los archivos grandes requieren:

* Multipart upload.
* Reintentos parciales.
* Control de memoria.
* Streaming.
* Manejo de timeouts.
* Seguimiento por partes.

### Versiones

La migración inicial podría copiar únicamente la versión actual.

Migrar el historial completo requiere considerar:

* Version IDs.
* Delete markers.
* Metadata por versión.
* Orden cronológico.
* Compatibilidad del destino.

### Metadata

No toda la metadata puede representarse de la misma forma en todos los proveedores.

Debe distinguirse entre:

* Metadata HTTP.
* Metadata personalizada.
* Tags.
* ACLs.
* Políticas.
* Configuración del bucket.

### Permisos

Las políticas de seguridad no son necesariamente portables.

Amazon IAM, usuarios de MinIO y mecanismos de Ceph RGW utilizan modelos diferentes.

Por lo tanto, la migración de datos y la migración de seguridad deben tratarse como procesos separados.

### Ventana de corte

Debe definirse:

* Duración.
* Impacto.
* Responsables.
* Validaciones.
* Criterios de éxito.
* Criterios de rollback.
* Comunicación a usuarios.

### Costos de egreso en cloud pública

Mover datos fuera de una nube pública puede generar costos de transferencia.

Deben considerarse:

* Volumen total.
* Región.
* Destino.
* Tráfico entre regiones.
* Número de solicitudes.
* Tiempo de migración.
* Posible uso de enlaces privados.
* Costos de almacenamiento temporal.
