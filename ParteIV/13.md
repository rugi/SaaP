## 13. Migrador JavaFX

El segundo laboratorio será una aplicación de escritorio desarrollada con JavaFX.

### Objetivo

Demostrar visualmente la movilidad de los datos entre diferentes proveedores compatibles con S3.

### Arquitectura

```text
JavaFX UI
    |
    v
MigrationService
    |
    +------ Source S3Client
    |
    +------ Target S3Client
```

La lógica de migración deberá permanecer separada de la interfaz.

Estructura sugerida:

```text
storage-migration-core
storage-migration-javafx
```

### Conexiones origen y destino

La interfaz permitirá configurar:

* Endpoint.
* Región.
* Access key.
* Secret key.
* Bucket.
* Path-style access.
* TLS.
* Timeout.

### Progreso

La aplicación mostrará:

* Objetos encontrados.
* Objetos pendientes.
* Objetos copiados.
* Objetos omitidos.
* Errores.
* Bytes transferidos.
* Porcentaje de avance.
* Tiempo transcurrido.

### Reintentos

Los errores transitorios deberán manejarse con:

* Número máximo de intentos.
* Backoff.
* Registro del último error.
* Reanudación.
* Lista de objetos fallidos.

### Checksums

La aplicación calculará un checksum independiente del ETag.

Ejemplo:

```text
SHA-256
```

Esto es importante porque el ETag no siempre representa directamente el hash del contenido, especialmente en multipart uploads.

### Reporte

Al finalizar, se generará un reporte.

Ejemplo:

```text
Migration ID: 2026-001
Source: MinIO
Target: Ceph RGW
Objects discovered: 1,000
Objects migrated: 998
Objects skipped: 1
Objects failed: 1
Bytes transferred: 4.8 GB
Checksum errors: 0
Status: PARTIALLY_COMPLETED
```

### Migración reversible

La aplicación permitirá intercambiar origen y destino.

Ejemplos:

```text
Amazon S3 -> MinIO
MinIO -> Ceph RGW
Ceph RGW -> Amazon S3
```

La reversibilidad no implica que todas las capacidades específicas del proveedor puedan trasladarse.

La primera versión se concentrará en:

* Contenido.
* Object key.
* Content type.
* Metadata personalizada.
* Tamaño.
* Checksum.
