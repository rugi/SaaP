## 19. Lecciones

### Elegir el modelo antes que el producto

La primera pregunta no debe ser:

> ¿Qué producto utilizaremos?

Debe ser:

> ¿Qué patrón de almacenamiento requiere la aplicación?

Primero se elige entre:

* Object.
* Block.
* File.
* Ephemeral.
* Archive.

Después se evalúa el producto.

### Diseñar contra un contrato

La lógica de negocio debe depender de una abstracción estable.

```text
Aplicación
    |
    v
ObjectStorage
    |
    v
Proveedor compatible
```

### Separar datos, configuración y políticas

Los datos representan el contenido.

La configuración define:

* Endpoint.
* Región.
* Bucket.
* Timeouts.
* Credenciales.

Las políticas definen:

* Quién puede acceder.
* Qué operaciones puede realizar.
* Sobre qué recursos.

Estas responsabilidades no deben mezclarse.

### La portabilidad debe probarse

Una arquitectura no es portable solo porque utiliza una interfaz.

Debe verificarse mediante:

* Pruebas de contrato.
* Ejecución contra distintos proveedores.
* Migración de objetos.
* Validación de checksums.
* Pruebas funcionales.
* Simulación de rollback.

### Ceph es una plataforma

Ceph no debe presentarse únicamente como reemplazo de MinIO.

MinIO se concentra en Object Storage.

Ceph proporciona:

```text
RGW    -> Object
RBD    -> Block
CephFS -> File
```

Su valor aparece cuando una organización necesita una plataforma de almacenamiento más amplia y acepta su complejidad operativa.
