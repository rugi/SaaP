## 9. Aplicación de catálogo

La primera aplicación del laboratorio será un catálogo web de productos.

### Objetivo

Demostrar que la misma aplicación puede almacenar y consultar imágenes en diferentes proveedores compatibles con S3.

### Modelo

Entidad conceptual:

```text
Product
- id
- name
- description
- price
```

Entidad de imagen:

```text
ProductImage
- id
- productId
- objectKey
- contentType
- size
- checksum
- mainImage
- createdAt
```

### Upload

La aplicación permitirá:

* Seleccionar una imagen.
* Validar formato.
* Validar tamaño.
* Generar una object key.
* Subir el archivo.
* Calcular checksum.
* Registrar metadata.

### Download

La descarga podrá realizarse de dos maneras:

1. La aplicación descarga y transmite el contenido.
2. La aplicación genera una URL firmada.

La segunda opción reduce la carga sobre el backend.

### Presigned URLs

La aplicación podrá generar URLs temporales.

Ejemplo:

```text
GET /api/products/123/images/main/url
```

Respuesta:

```json
{
  "url": "https://...",
  "expiresInSeconds": 300
}
```

### Metadata

Se conservará al menos:

* Object key.
* Content type.
* Tamaño.
* Checksum.
* Identificador del producto.
* Fecha de carga.

### Eliminación

La eliminación deberá coordinar:

1. Eliminación en Object Storage.
2. Eliminación del registro en la base de datos.
3. Manejo de errores parciales.
4. Posibles reintentos.

### Pruebas de contrato

La misma suite deberá ejecutarse contra todos los proveedores.

```text
ObjectStorageContractTest
├── shouldUploadObject
├── shouldDownloadObject
├── shouldDeleteObject
├── shouldDetectExistingObject
├── shouldPreserveContentType
├── shouldPreserveMetadata
├── shouldGeneratePresignedUrl
└── shouldListObjectsByPrefix
```

Estas pruebas demostrarán que el contrato mínimo es realmente portable.
