## 8. Diseñar una capa portable

El objetivo es evitar que la lógica de negocio conozca directamente al proveedor.

### SDK común

La aplicación utilizará el AWS SDK for Java como cliente común para la API S3.

Arquitectura conceptual:

```text
Aplicación
    |
    v
StorageService
    |
    v
AWS SDK for Java
    |
    +------ Amazon S3
    |
    +------ MinIO
    |
    +------ Ceph RGW
```

### Configuración externa

Los valores específicos del proveedor deben permanecer fuera del código.

Ejemplos:

```yaml
storage:
  endpoint: http://localhost:9000
  region: us-east-1
  bucket: product-images
  access-key: ${STORAGE_ACCESS_KEY}
  secret-key: ${STORAGE_SECRET_KEY}
  path-style-access: true
```

Los elementos que pueden cambiar son:

* Endpoint.
* Región.
* Credenciales.
* Bucket.
* Path-style access.
* Timeouts.
* Configuración TLS.

### Ports and adapters

La aplicación definirá un puerto independiente del proveedor.

```java
public interface ObjectStorage {

    void upload(
        String objectKey,
        String contentType,
        long contentLength,
        InputStream content
    );

    InputStream download(String objectKey);

    void delete(String objectKey);

    boolean exists(String objectKey);

    URI createPresignedDownloadUrl(
        String objectKey,
        Duration expiration
    );
}
```

La implementación puede utilizar el cliente S3.

```text
Dominio
   |
   v
ObjectStorage
   |
   v
S3ObjectStorageAdapter
   |
   v
S3Client
```

### Object keys neutrales

Las keys no deben incluir información específica del proveedor.

Correcto:

```text
tenants/11111111/products/123/images/main.webp
```

Incorrecto:

```text
amazon-s3/us-east-1/product-images/123/main.webp
```

### No almacenar URLs absolutas

No debe almacenarse una URL como:

```text
http://localhost:9000/product-images/products/123/main.webp
```

La base de datos debería guardar información neutral:

```text
object_key: products/123/main.webp
content_type: image/webp
size: 184203
checksum: sha256:...
```

La URL debe construirse o firmarse en tiempo de ejecución.

### Manejo de credenciales

Las credenciales no deben incluirse directamente en el código ni en el repositorio.

Alternativas:

* Variables de entorno.
* AWS IAM Roles.
* IAM Roles for Service Accounts.
* Kubernetes Secrets.
* Docker Secrets.
* Secret managers.
* Credenciales temporales.
