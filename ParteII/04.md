## 4. Fundamentos de Object Storage

Object Storage almacena información como objetos independientes dentro de uno o más buckets.

### Objetos

Un objeto representa una unidad completa de información.

Puede ser:

* Una imagen.
* Un documento.
* Un video.
* Un archivo comprimido.
* Un log.
* Un backup.
* Un modelo de inteligencia artificial.

### Keys

La key identifica un objeto dentro de un bucket.

Ejemplo:

```text
products/123/images/main.webp
```

La key debe diseñarse cuidadosamente porque puede representar:

* Organización lógica.
* Tenant.
* Producto.
* Fecha.
* Tipo de archivo.
* Versión.
* Entorno.

Ejemplo multi-tenant:

```text
tenants/11111111/products/123/images/main.webp
```

### Buckets

Un bucket es un contenedor lógico de objetos.

Puede utilizarse para separar:

* Aplicaciones.
* Ambientes.
* Tipos de contenido.
* Clientes.
* Políticas de seguridad.
* Ciclos de vida.

Ejemplos:

```text
product-images-prod
product-images-qa
airflow-logs-prod
application-backups
```

### Metadata

La metadata describe al objeto.

Ejemplos:

* Content type.
* Tamaño.
* Fecha de creación.
* Propietario.
* Checksum.
* Etiquetas.
* Identificador de negocio.

Metadata típica:

```text
Content-Type: image/webp
Content-Length: 184203
x-amz-meta-product-id: 123
x-amz-meta-tenant-id: 11111111
```

### Prefijos

Los prefijos permiten agrupar objetos mediante una convención de nombres.

Ejemplo:

```text
products/123/
products/123/images/
products/123/documents/
```

No representan necesariamente directorios reales.

Son segmentos de la key utilizados para listar y organizar objetos.

### Inmutabilidad conceptual del objeto

Object Storage trata cada objeto como una unidad completa.

Cuando cambia su contenido, normalmente se realiza una nueva operación de escritura que reemplaza el objeto anterior o crea una nueva versión.

No está diseñado para modificar pequeños bloques internos de forma continua, como ocurre en una base de datos.

### Multipart upload

Multipart upload permite dividir archivos grandes en varias partes.

Flujo general:

1. Iniciar la carga multipart.
2. Dividir el archivo.
3. Subir las partes.
4. Reintentar únicamente las partes que fallen.
5. Completar la carga.
6. Construir el objeto final.

Beneficios:

* Mayor tolerancia a fallos.
* Paralelización.
* Reintentos parciales.
* Mejor manejo de archivos grandes.
